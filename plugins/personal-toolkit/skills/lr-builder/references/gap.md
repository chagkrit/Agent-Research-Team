# เฟส 4 — Gap Argumentation (วิธีสองสาย)

gap ที่อ่อนคือจุดตายอันดับต้นของ manuscript — reviewer ที่ 2 มักถล่มตรงนี้ก่อนจุดอื่น เฟสนี้มีหน้าที่เดียว: พิสูจน์ว่า gap ของผู้ใช้มีจริง — หรือบอกตรง ๆ ว่ายังไม่มี

## หลักการ: gap ต้องผ่านการทดสอบสองทิศทาง

**สายเกิด (เดินหน้า)** — จาก theme-map.md ไล่ให้เห็นว่าสนามความรู้สะสมอะไรมาแล้วบ้าง และเส้นทางของหลักฐานพามาหยุดตรงไหน gap ต้องเป็นจุดที่ "โซ่ความรู้ขาด" จริง ไม่ใช่จุดที่แค่ยังไม่มีใครเดินผ่าน

**สายดับ (ย้อนกลับ / counterfactual)** — คำถามบังคับ: **"ถ้างานวิจัยของผู้ใช้ไม่เกิดขึ้น คำถามอะไรในสนามนี้ที่ยังตอบไม่ได้"**
- ตอบได้ชัด → gap จริง
- ตอบไม่ได้ หรือคำตอบคือ "ก็แค่ยังไม่มีใครทำ" → gap ปลอม กลับไป theme-map.md หาใหม่

gap ที่ผ่านต้องผ่าน **ทั้งสองสาย** — สายเกิดยืนยันว่ามีเส้นทางหลักฐานนำมาถึง สายดับยืนยันว่าถ้าไม่อุด ความรู้ขาดจริง

## แผนที่ gap ปลอมที่พบบ่อย (ตรวจก่อนเสนอผู้ใช้เสมอ)

| รูปแบบ | ทำไมอ่อน | จะแข็งได้เมื่อ |
|---|---|---|
| "ยังไม่มีใครศึกษาในบริบทไทย/จังหวัด X" | บริบทใหม่อย่างเดียวไม่ใช่ gap — ต้องมีเหตุผลว่าบริบทนั้นจะเปลี่ยนคำตอบ | ชี้กลไกได้ว่าทำไมผลจากบริบทอื่นน่าจะใช้ไม่ได้ (วัฒนธรรม ระบบ นโยบาย ต่างยังไง) โดยอ้างหลักฐานจาก matrix |
| "ยังไม่มีใครใช้ทฤษฎี Y กับเรื่องนี้" | การสลับเลนส์ไม่ใช่ gap ถ้าเลนส์เดิมตอบได้ดีอยู่แล้ว | แสดงว่าเลนส์เดิมอธิบายปรากฏการณ์บางส่วนไม่ได้ และทฤษฎี Y อุดตรงนั้นได้ |
| "งานเก่าใช้กลุ่มตัวอย่างเล็ก/วิธีอ่อน" | ข้อจำกัดเชิงวิธีไม่ใช่ gap เชิงความรู้โดยอัตโนมัติ | แสดงว่าข้อจำกัดนั้นทำให้ข้อสรุปหลักของสนาม "ยังเชื่อไม่ได้" จริง |
| "ผลการศึกษายังขัดแย้งกัน" | ความขัดแย้งเป็นวัตถุดิบ ไม่ใช่ gap สำเร็จรูป | เสนอ "ตัวแปรที่อาจอธิบายความขัดแย้ง" และงานของผู้ใช้ออกแบบมาทดสอบตัวแปรนั้น |

## โครงของ gap-argument.md

```markdown
# Gap argument
อัปเดต: [วันที่] / สถานะ: [ร่าง | ผู้ใช้ยืนยันแล้ว]

## สายเกิด — สนามรู้อะไรแล้ว
(3–6 ย่อหน้าสังเคราะห์จาก theme-map พร้อม citation จาก matrix เท่านั้น
เดินจากกว้าง → แคบ → จุดที่โซ่ขาด)

## สายดับ — ถ้างานนี้ไม่เกิดขึ้น
คำถามที่ยังตอบไม่ได้คือ: "..."
หลักฐานว่าตอบไม่ได้จริง: (งานใกล้เคียงที่สุดคือ ... แต่ตอบไม่ได้เพราะ ...)

## ผลทดสอบ gap ปลอม
(ไล่เช็คกับตารางข้างบนทีละแบบ ระบุว่ารอดเพราะอะไร)

## ประโยค gap สุดท้าย (สำหรับใช้ในบทจริง)
(2–4 ประโยค คม ตรง อ้างอิงครบ)

## จุดอ่อนที่เหลือ
(ความเปราะของ argument นี้ที่ผู้ใช้ควรรู้และเตรียมคำตอบไว้ล่วงหน้า สำหรับตอบ reviewer comment ที่คาดว่าจะโดนถาม — ห้ามว่าง
ทุก gap มีจุดอ่อน การมองไม่เห็นแปลว่ายังหาไม่เจอ)
```

## กติกาของเฟสนี้

- รัน `ls -la -t` ที่ `references/` ก่อนเริ่มและบันทึกไฟล์ current; ห้ามเชื่อ memory/note อย่างเดียว
- ทุก citation ที่ใช้พิสูจน์ gap ต้องมาจาก matrix row ที่มี live PubMed/Semantic Scholar/Consensus provenance, PMID/DOI ที่ resolve จริง, และ verified Q1/Q2 status ครบ
- วิพากษ์ตรง ห้ามเกรงใจ — gap ที่ถูกฆ่าตายในเฟสนี้คือ gap ที่ไม่ต้องไปตายต่อหน้ากรรมการ
- ถ้า gap ของผู้ใช้ไม่ผ่าน ให้เสนอ gap ทางเลือก 1–2 ตัวจาก "จุดที่เงียบ" และ "จุดที่ขัดแย้ง" ใน theme-map พร้อมผลทดสอบเบื้องต้นของแต่ละตัว
- การเลือก gap สุดท้ายเป็นการตัดสินใจของผู้ใช้ (และ co-author/PI) — skill มีหน้าที่ทดสอบ ไม่ใช่ตัดสินแทน
